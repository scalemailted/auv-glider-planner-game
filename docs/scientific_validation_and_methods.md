# Scientific Validation and Methods

SCI-VALID-R2A establishes the public Methods & Validation route and a versioned, machine-readable validation baseline for ANCHOR Alpha. The route presents evidence generated by package and scientific tests. It does not define scientific truth, change scientific models, or certify operational use.

## Scope

The validation baseline is an evidence index for deterministic software behavior, numerical checks, physical-plausibility checks, known limitations, and reproducibility commands. It separates these evidence levels:

| Evidence level | Meaning |
| --- | --- |
| SOFTWARE_VERIFIED | Software contract, schema, roundtrip, dependency, browser-safety, or deterministic fixture behavior is verified. |
| NUMERICALLY_VERIFIED | Manufactured or analytic numeric checks pass within declared tolerances. |
| PHYSICALLY_PLAUSIBLE | The synthetic behavior respects an educational physical constraint or stated plausibility rule. |
| EXTERNALLY_COMPARED | A quantitative comparison to an external reference fixture is present. |
| OPERATIONALLY_VALIDATED | Operational field validation is present. |
| NOT_YET_EVALUATED | Evidence is intentionally missing or deferred. |
| NOT_APPLICABLE | The claim does not apply to that component. |

Passing software or visual tests is not represented as oceanographic validation. ANCHOR remains a deterministic synthetic research-and-education sandbox, not an operational ocean forecast or certified vehicle-navigation system.

COLAB-BENCH-R1 uses this baseline as context for external classical planner comparisons. The notebook reads `validation/manifest.json` when available, records the baseline digest in reproducibility manifests, and links benchmark results to stated limitations. It does not convert the validation baseline into an operational-certification claim.

## Official Baseline Artifacts

| Artifact | Role |
| --- | --- |
| validation/manifest.json | Official manifest listing validation reports, digests, status summaries, evidence-level summaries, and suitability decisions. |
| validation/reports/*.json | Per-component machine-readable claim/evidence reports. |
| validation/data/validation_overview.json | Compact overview for notebooks, classroom review, and public inspection. |
| packages/validation/src/index.js | Pure validation contract package for claims, evidence records, reports, manifests, references, digests, and public summaries. |
| packages/validation/MODEL_CARD.md | Package scope, limitations, ownership, and claim-boundary model card. |
| schemas/scientific-validation-report.schema.json | Codec/schema registration for anchor.scientific-validation-report. |
| schemas/scientific-validation-manifest.schema.json | Codec/schema registration for anchor.scientific-validation-manifest. |
| tools/science/build_validation_baseline.mjs | Deterministic baseline builder. Default mode compares checked-in artifacts; --update rewrites them intentionally. |
| tools/tests/scientific_validation.test.mjs | Consolidated Node regression for validation contracts, baseline integrity, codec registration, visibility boundaries, and claim/evidence consistency. |

## Methods Route

The Product Hub includes Methods & Validation as a top-level route. It shows:

- official baseline id and digest
- component reports and claim counts
- status and evidence-level summaries
- selected claim details with method, metric, measured value, units, threshold, tolerance, threshold rationale, interpretation, limitations, and reference roles
- Plain Language and Technical Detail modes
- downloadable manifest, report, summary CSV, raw metric CSV, and plot data
- a lightweight exploratory local check that is clearly not part of the official baseline
- debug state at globalThis.ANCHOR_SCIENTIFIC_VALIDATION_DEBUG

The browser route reads the official JSON artifacts. It does not mutate them, recompute scientific equations, or use hidden truth.

## Component Evidence Inventory

| Component | Current evidence shape | Boundary |
| --- | --- | --- |
| Bathymetry | Software, numeric, and plausibility checks from package fixtures and manufactured cases. | Synthetic terrain regression, not external survey validation. |
| Currents | Software, numeric, and plausibility checks for deterministic 4D current artifacts and vertical structure. | Synthetic current benchmark, not calibrated HYCOM/Copernicus forecast skill. |
| Scalar processes | Software and numeric checks for scalar artifacts, samplers, and depth-aware values. | Teaching/manufactured fields, not ecological or biogeochemical forecast validation. |
| Environment | Software and plausibility checks for artifact composition, provenance, identity, and public-safe sampling. | Composition contract, not an external coupled-ocean validation. |
| Glider dynamics | Software and plausibility checks for educational glider route execution metadata. | Simplified kinematic mission simulator, not vehicle certification. |
| Sampling observations | Software checks for public observation metadata and depth/time provenance. | Public-safe observation contract, not real sensor calibration. |
| Mission simulator | Software checks for deterministic package authority and mission transitions. | Referee/runtime regression, not a real-world autonomy validation. |
| Scoring | Software checks for official scoring contracts and deterministic score identity. | Gameplay/benchmark scoring, not a universal science-validity score. |
| Codecs/reproducibility | Software checks for codec registry, schema alignment, and roundtrip behavior. | Transport contract only; it does not validate scientific truth. |

## Reproduction

Compare checked-in artifacts against the deterministic builder output:

```bash
node tools/science/build_validation_baseline.mjs
```

Intentionally refresh the official baseline after reviewing changes:

```bash
node tools/science/build_validation_baseline.mjs --update
```

Run the consolidated validation test:

```bash
node tools/tests/scientific_validation.test.mjs
```

Run focused browser coverage for the public route:

```bash
node ./node_modules/@playwright/test/cli.js test tests/e2e/scientific_validation_methods.spec.js --reporter=line --workers=1
```
