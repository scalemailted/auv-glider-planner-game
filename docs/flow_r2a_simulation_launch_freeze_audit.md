# FLOW-R2A.1 Simulation Launch Freeze Audit

FLOW-R2A.1 stabilizes the volumetric-current launch path. It does not add new current physics, tracers, WebGPU, a planner, scoring changes, or a renderer-authority change.

## Findings

The launch-freeze risk came from repeated or unsafe current-field work on the browser main thread:

- `OceanCurrentFieldSampler.sampleOceanCurrent` could normalize and digest full fields from a sampling path.
- Synthetic current cubes could be regenerated by presentation view-model construction instead of reused for the mission session.
- The render view model could clone or resample more current data than needed for glyph presentation.
- Single-point axes in current sampling could recurse through nearest-index lookup in browser execution.
- Current-glyph failures were presentation failures but could previously surface as runtime breakage instead of degrading cleanly.
- Returning from Simulation to Planning left the Mission Workspace execute gate marked in progress, causing later Execute clicks to be treated as duplicates.

## Hardening

- `SimulationLaunchProfiler` publishes `globalThis.ANCHOR_SIMULATION_LAUNCH_DEBUG` with launch stages, current counters, renderer counts, warnings, failures, and memory estimates.
- The synthetic current cube adapter caches one mission-world current cube per level/config session.
- The ocean current sampler caches prepared samplers and keeps hot sampling free of normalization, digesting, cube building, and full-field cloning.
- The water-column explorer caches compact render samples instead of copying full current cubes for display.
- The Three.js current glyph layer uses one instanced presentation layer, reuses buffer capacity, hides invalid vectors, and can fail soft.
- `?currentDisplay=safe` disables current-glyph presentation only. Canonical mission physics still uses the current field.
- Malformed canonical current fields now fail visibly and cleanly whether rejection happens before or during `SimulationScene` construction.
- Re-entering Planning resets the execute-in-progress gate so a second launch from the same plan can run.
