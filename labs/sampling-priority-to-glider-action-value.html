1. The problem: sampling is not hotspot chasing

The central teaching message is simple: the best sample is not always the brightest cell. The best scientific target is not always the best glider action.

A bright event center may already be well understood. A lower-intensity boundary may be uncertain and scientifically valuable. A stale region may deserve a revisit. A high-priority cell may still be unreachable, current-opposed, hazardous, expensive, late, or redundant for one specific glider.

Event intensity is not sampling priority

A bloom center may have high intensity but low priority if it is already well understood. A plume boundary may have lower intensity but high priority if it is uncertain. A stale region may have high priority because the last sample is old.

What to notice: the brightest event cell may not be the highest-priority sample.

3. Global sampling priority A_global(x,y,t)

The Sampling Priority Demo computes a global, vehicle-independent science-priority map. It answers: where would a measurement be scientifically useful next?

A_global(x,y,t) = w_value * beliefRoi + w_uncertainty * expectedUncertainty + w_boundary * boundaryStrength + w_forecast * forecastValidation + w_unknown * hiddenEventProbability + w_staleness * staleness - w_hazard * hazard - w_redundancy * recentSamplePenalty
In words: This map asks where a sample would be scientifically useful, before deciding whether a specific glider can get there.

The terms can represent believed scientific value, uncertainty reduction, edge mapping, forecast validation, hidden-event follow-up, revisit value, hazards, and recent-sample redundancy. It does not evaluate currentAssist, crossCurrentRisk, energyCost, vehicle assignment, or route feasibility.

4. Candidate sample points

A continuous-looking priority map still has to become a short list of proposed sampling locations. A candidateSamplePoint is one such proposal. It can be selected as a diverse top-K cell, a local maximum, a boundary point, an uncertainty point, a hidden-event follow-up, a staleness revisit, or a forecast-validation point.

What a candidate is

A compact teaching object: location, priority score, reason label, and component breakdown.

What a candidate is not

It is not an executable route, not a vehicle controller command, and not a guarantee that one glider should go there now.

5. Why flow changes the decision

Currents change whether a direct target is cheap, slow, risky, or late. A target may be scientifically useful but current-opposed. Another target may be lower priority but aligned with flow, reachable sooner, and cheaper in energy.

Sampling priority is not glider action value

A high-priority target can be a bad glider action if the current opposes travel, cross-current drift is high, energy cost is high, or the glider arrives too late.

6. Glider action value Q_glider(g,x,y,t)

The Flow-Coupled Sampling Demo computes a glider-specific direct-target action-value map. It answers: given a global science-priority map, where should this specific glider actually go now?

Q_glider(g,x,y,t) = w_priority * A_global(x,y,t_arrival) + w_assist * currentAssist + w_future * futurePriority - w_travel * travelCost - w_energy * energyCost - w_current * currentOpposition - w_cross * crossCurrentRisk - w_time * missedWindowPenalty - w_hazard * hazardPenalty - w_redundancy * redundancyPenalty
In words: This map asks whether a scientifically useful location is a good target for this glider right now.

Unlike A_global, Q_glider depends on the selected glider, its start, speed and budgets, the flow field F(x,y,t), reachability, direct-leg timing, hazards, and teammate/recent-sample redundancy.

7. Example: high-priority target, bad glider action

A high-priority target can be a bad action when the selected glider must fight current, spend too much energy, cross a strong lateral flow, or arrive after the useful window. This does not mean the science target is bad. It means this glider, at this time, is a poor match for that target.

In words: the sample would be scientifically useful.

In words: this direct action is costly, risky, late, or redundant.

8. Example: lower-priority target, better current assist

A lower-priority target can become the better glider action if the current helps the vehicle reach it, while the brighter target lies up-current. That is why the S2 demo makes currentAssist and currentOpposition visible components instead of hiding them inside one score.

Widget 3. Current Assist / Opposition

Increase flow strength. Target B has lower science priority, but it may become a better glider action when the current helps the leg.

What to notice: flow can make a lower-priority target more attractive.

9. Example: future intercept instead of chasing the center

A moving feature should not always be chased at its current center. If the glider will arrive later, the action-value map should consider A_global(x,y,t_arrival) and futurePriority. In the Flow-Coupled Sampling Demo, the downstream intercept scenario shows why a useful future target can differ from the brightest current cell.

Plain language: sample where the feature will be useful when the glider arrives, not only where it is brightest now.

10. Example: two gliders and redundancy

Two gliders should not automatically chase the same candidate. If confirmation is not the mission, the team should reduce duplicate samples and spread effort across useful targets. This is why S2 includes recent-sample and teammate redundancy as penalties, not hidden side effects.

Widget 4. Redundancy Preview

Toggle the redundancy penalty and watch candidate ranking change for the selected glider.

What to notice: multiple gliders should avoid wasting effort on the same target unless confirmation is the mission.

11. What this still is not: not route planning yet

Action value is not route planning

S2 evaluates one-step target options. A full route planner must sequence multiple waypoints over time.

  • This is not a calibrated ocean model.
  • This is not a production data-assimilation system.
  • This is not a GP/GMRF planner.
  • This is not full route planning.
  • This is not a glider vehicle controller.
  • This is not a MARL environment yet.

But it is a useful bridge between belief-based sampling maps and route planning.
