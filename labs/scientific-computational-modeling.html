1. What is a scientific computational model?

A scientific model is a simplified representation of a real or imagined system. A computational model makes the representation executable: it stores state, applies rules or equations, advances time, generates predictions, and lets people test whether the behavior matches the intended phenomenon.

CA is a rigorous first step in computational modeling, not a shortcut for fake hotspots.

Model Loop Widget

This widget steps through the basic cycle: state → rule/equation → next state → observation → validation.

What to notice: a model is useful only when its assumptions and validation target are explicit.

2. Why model instead of only observe?

Scientists observe the world, but observation alone is often sparse, noisy, expensive, delayed, or impossible at every place and time. A model lets scientists ask what might happen between measurements, compare competing assumptions, plan future observations, and decide where a vehicle should sample next.

The best sample is not always the brightest cell. The best sample is often the one that most improves the mission's belief about a moving, uncertain ocean feature under flow, depth, energy, risk, and communication constraints.

3. State, rules, parameters, and outputs

ANCHOR uses this structure repeatedly:

State

What is true right now?

Rule / equation

How does the state change?

Parameter

What controls the behavior?

Observation

What can we measure?

Prediction

What does the model say should happen?

Validation

Did the model behave like the intended phenomenon?

X(t+1) = F(X(t))
In words: the next whole-world state is produced by applying an update function to the current whole-world state.
x_i(t+1) = f(x_i(t), N_i(t), theta)
In words: the next state of cell i depends on its current state, its neighborhood, and parameters.
X(t+1) ~ P(X(t+1) | X(t))
In words: the next state is sampled from a probability model conditioned on the current state.
z_i = T(x_i,y_i,t_i) + epsilon_i
In words: observation i is the hidden truth at a place and time plus sensor or environmental noise.
belief_next = update(belief_current, observation, model)
In words: new evidence changes what the mission believes about the world.

4. Deterministic models

A deterministic model gives the same future when it starts from the same state with the same parameters. This is useful for teaching because students can replay a scenario and inspect cause and effect.

same initial state + same rule + same parameters = same future

Deterministic vs Stochastic Widget

Step the same initial pattern as a deterministic update and as a seeded stochastic possible outcome.

What to notice: deterministic replay is exact; stochastic replay is repeatable only because the random choice is seeded.

5. Cellular automata as a first modeling language

Cellular automata are discrete dynamical systems. A CA has cells, a state set, an initial condition, neighborhoods, and local update rules. Local rules induce global field evolution.

CA is a rigorous first step in computational modeling, not a shortcut for fake hotspots. It teaches state, neighborhood, update rule, time step, validation, and emergent behavior before students move to continuous fields, uncertainty, and route-aware mission criteria.

Local Rule / Neighborhood Widget

Click neighbor cells and change the rule to preview one local update.

What to notice: a local rule reads nearby cells, but repeated updates can create large-scale structure.

6. Famous CA examples

These examples are useful because each isolates a modeling idea. They are teaching models, not final ocean simulators.

Exact CA teaching model

Conway's Game of Life

Teaches: birth, death, emergence, oscillators, and moving structures.

State vocabulary: alive, inactive.

Local update idea: a live cell survives with two or three neighbors; an inactive cell is born with exactly three neighbors.

Emerges: still lifes, oscillators, gliders, and patch reorganization.

What it is not: not an ocean model.

Mission connection: local rules can create global structure that later becomes a process layer.

Exact CA teaching model

Forest Fire CA

Teaches: fronts, susceptible fuel, ignition, and consumed trails.

State vocabulary: empty, tree/susceptible, burning, consumed.

Local update idea: susceptible cells ignite near burning neighbors; burning cells cool or become consumed.

Emerges: propagating boundaries and fragmented trails.

What it is not: not a calibrated wildfire, bloom, or hydrodynamic model.

Mission connection: fronts teach why boundaries can be more valuable than centers.

Exact CA teaching model

SIR / Epidemic CA

Teaches: spread, recovery, immunity, and local contact pressure.

State vocabulary: susceptible, infected, recovered.

Local update idea: susceptible cells near infected neighbors can become infected, then recover.

Emerges: expanding patches and recovery shadows.

What it is not: not a public-health forecast or ocean forecast.

Mission connection: it frames diffusive spread and uncertain contact zones.

Exact CA teaching model

Greenberg-Hastings / Excitable Media

Teaches: wave fronts, refractory memory, and recovery cycles.

State vocabulary: resting, excited, refractory.

Local update idea: resting cells excite near active neighbors, then pass through refractory states.

Emerges: waves, spirals, and recovery trails.

What it is not: not a full reaction-diffusion solver.

Mission connection: it explains moving crests and recent-activity wakes.

Exact CA teaching model

Sandpile / Avalanche

Teaches: thresholds, buildup, cascades, and sudden releases.

State vocabulary: load, threshold, toppled/released.

Local update idea: load accumulates until a threshold redistributes to neighbors.

Emerges: rare cascades and bursty activity.

What it is not: not a calibrated geophysical hazard model.

Mission connection: it motivates monitoring low-probability high-impact transitions.

Exact CA teaching model

Wa-Tor / Predator-Prey

Teaches: interacting populations, pursuit, resource cycles, and migration waves.

State vocabulary: empty, prey, predator.

Local update idea: prey move or reproduce; predators move toward prey and may starve.

Emerges: cycles, pursuit fronts, and patch collapse.

What it is not: not a calibrated ecosystem model.

Mission connection: it shows coupled state variables in one grid.

Exact CA teaching model

Traffic CA

Teaches: congestion, density waves, blockage, and release.

State vocabulary: empty, occupied, moving, jammed.

Local update idea: occupied cells advance if downstream space is open.

Emerges: jams, gaps, and stop-go waves.

What it is not: not a nautical traffic planner.

Mission connection: it foreshadows reachability and route-cost constraints.

Exact CA teaching model

Wireworld

Teaches: signal propagation, pathways, memory, and logic-like structures.

State vocabulary: empty, conductor, signal head, signal tail.

Local update idea: conductor cells activate when adjacent to a signal head; heads become tails.

Emerges: pulses along constrained paths.

What it is not: not a communications network simulator.

Mission connection: it shows process propagation along permitted structure.

7. Update functions and field evolution

An update function is the executable rule. In a grid model, the local update runs for every cell, and the collection of local updates creates the next field.

current field X(t)
neighborhood reads N_i(t)
local rule f(...)
next field X(t+1)

8. Stochastic models

Stochastic models include probability. They are useful when the same current state can plausibly lead to multiple futures, or when the hidden state is not fully known.

X(t+1) ~ P(X(t+1) | X(t))
In words: the future is a distribution of possible states, not one guaranteed state.

9. Uncertainty, belief, and hidden truth

More science-aligned mission models distinguish hidden truth, forecast state, observations, belief, uncertainty, hidden-event probability, and visible planning state. The vehicle rarely sees the full truth directly.

z_i = T(x_i,y_i,t_i) + epsilon_i
In words: a measurement is truth plus noise.
belief_next = update(belief_current, observation, model)
In words: the mission updates what it believes after it samples.

10. Fuzzy, continuous, and generalized CA

Generalized CA can be asynchronous, stochastic, multi-state, continuous or fuzzy, extended-neighborhood, or non-uniform. This is the bridge between binary teaching models and richer field models.

Fuzzy / Continuous CA Widget

Compare binary cell values against continuous intensity or membership values.

What to notice: a continuous field can still be updated on a grid, but it no longer claims every cell is simply on or off.

11. Validation: when is a model useful?

A model is useful when it supports a declared purpose. A teaching CA can be valid for showing emergence while still being invalid as a calibrated ocean simulator.

Useful validation question

Does this rule produce the intended local-to-global behavior?

Overclaim to avoid

This CA heatmap is not by itself a final ocean forecast or AUV adaptive-sampling priority.

Model fidelity ladder

1. Exact / famous CA examples

Adds: known rule systems.

More realistic because: it makes local dynamics explicit.

Still does not claim: calibrated environmental prediction.

Adds: event-layer analogs such as fronts, blooms, recovery, or freshness.

More realistic because: it maps rule behavior to mission-relevant process roles.

3. Generalized CA: stochastic, multi-state, fuzzy/continuous, extended-neighborhood, non-uniform

Adds: richer states, probabilities, continuous values, and heterogeneous rules.

More realistic because: natural systems are rarely binary and uniform.

Still does not claim: calibrated transport or inference.

ANCHOR place: Custom Composer / Rule Allocation Sandbox.

4. Deterministic update-function fields

Adds: explicit field update functions.

More realistic because: the process can be treated as a field model.

Still does not claim: uncertainty-aware belief.

ANCHOR place: Process Lab and future engine contracts.

5. Flow-coupled scalar fields

Adds: advection by current fields, diffusion, source/sink, and decay/growth terms.

More realistic because: ocean features move with flow.

Still does not claim: perfect forecast or observation model.

ANCHOR place: Flow Fields and Coupled Fields sandboxes.

6. Hidden truth vs forecast/belief fields

Adds: truth, expected state, belief, and uncertainty separation.

More realistic because: planners act with imperfect knowledge.

Still does not claim: production data assimilation.

ANCHOR place: Uncertainty / Forecast Demo.

7. Observation and sensor-noise models

Adds: measurement locations, timing, and noisy sensor readings.

More realistic because: gliders sample sparse data.

Still does not claim: full sensor calibration.

ANCHOR place: future observation-model sandbox.

8. GP/GMRF/data-assimilation-style belief models

Adds: structured posterior belief and update logic.

More realistic because: samples alter belief over space and time.

Still does not claim: this phase implements GP, GMRF, or EnKF inference.

ANCHOR place: future uncertainty engine.

9. Acquisition / sampling-priority models

Adds: value, uncertainty, boundary value, hidden-event suspicion, staleness, and cost.

More realistic because: sample choice depends on information gain and mission constraints.

Still does not claim: priority equals intensity.

ANCHOR place: stochastic coupled sampling spaces.

10. Route planning and multi-agent mission evaluation

Adds: route cost, flow assist/opposition, risk, energy, surfacing windows, redundancy, and regret.

More realistic because: vehicles must move through constraints.

Still does not claim: full operational autonomy.

ANCHOR place: Planner / Mission Evaluation and future benchmark modes.

12. From CA to more realistic mission models

CA / grid-process models are useful for teaching local update rules and generating simplified event/process layers.

More science-aligned environmental models use advection, diffusion, source/sink, decay/growth, flow coupling, hidden truth, forecast, belief, uncertainty, observations, data assimilation, and acquisition logic.

Mission-planning models use sampling priority, route cost, flow assist/opposition, hazard/risk, depth profile, energy, surfacing windows, redundancy, and regret.

13. How ANCHOR uses the model ladder

ANCHOR starts with CA and grid-process sandboxes because they are inspectable. Later sandboxes add flow, coupling, stochastic forecast/belief, observations, acquisition value, route constraints, debrief, and benchmarks.

CA → generalized CA / fuzzy CA → deterministic update functions → flow-coupled scalar fields → stochastic belief / uncertainty → acquisition / sampling priority → mission planning criteria
